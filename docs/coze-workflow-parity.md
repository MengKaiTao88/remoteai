## 节点能力

“可导入”指可以转换该节点的上游画布定义；“本地可编排”指能力已实现，
但原导出文件中的资源 ID、复杂端口或配置需要在 Remote AI 画布中重新设置。
这些状态不代表兼容上游所有 HTTP、Thrift、数据库结构或画布配置。

## 暂停、恢复和执行边界

- 运行时保存根画布及嵌套调用栈。栈中包含子画布、节点输出、变量、循环位置、
  已完成迭代结果和发布依赖版本。每完成一个叶节点即保存，再执行后续有副作用的步骤。
- 子工作流、列表批处理、按次数循环都可以暂停。重启后从当前问题继续，
  已创建的记录、已完成的工具调用和先前迭代不会因正常恢复而重放。
- 每个问题有唯一 `interaction.id`。`resume_run` / `resume_run_start` 必须携带
  `runId`、`interactionId`、`input`。状态和问题 ID 在同一事务中比较，
  防止并发回答、过期按钮或延迟请求覆盖下一个问题。
- MCP 使用 `coze_resume`，提供 `run_id`、`interaction_id`、`input`。
  只能恢复已发布且仍允许外部调用的工作流；草稿试运行不能通过 MCP 恢复。
- 运行中进程意外退出时，不能确认最后一次外部调用是否已生效。因此标记为“已中断”，
  不自动重试该副作用。等待用户输入的运行可以正常恢复。
- 发布运行使用完整的冻结依赖版本；循环执行中已加载的子画布也保存在调用栈中，
  暂停期间修改草稿不会改变该循环剩余迭代的画布。
- 循环体共享 `variables`，每次迭代的 `input.item` 和 `input.index` 独立。
  子工作流使用独立变量空间。`break` / `continue` 只控制当前循环。
- 普通执行最多 200 个节点、800 条边，嵌套最多 8 层，单个循环最多 100 次。
  每个主动运行阶段有时间上限；人机等待时间不计入下一次恢复阶段。
- 实时事件按序号读取，前端轮询保持单次请求在途。取消会传播到嵌套步骤和模型流；
  已提交的外部请求或已完成的数据写入不会被撤销。

## 导入和代码运行的明确差异

- 原画布中未适配的节点、嵌套 blocks、多出口端口、应用变量引用或不支持的模型配置
  会被拒绝，避免只导入部分节点却让用户误以为整个工作流已经迁移。
  可在本地画布中重建这些能力；导入的模型还需选择本地代理提供的对应模型。
- Python 使用随独立包分发的 Rust 解释器子进程，不依赖系统 Python。
  支持的数据处理语法和标准库以运行器能力为准，不等于任意 CPython 第三方包环境。
  JavaScript / TypeScript 使用隔离的 QuickJS；TypeScript 先由 Rust 编译器去除类型。
  各语言均限制时间、内存和输出，不提供任意文件、网络或进程能力。
- 批处理按顺序执行，不复刻上游任意并行度和重试策略。
  原版模型技能、自动抽取问答字段、多级异常端口和自动重试配置不是完整画布兼容项。

## 验证依据

- 2026-10-11 对照本机开源 Coze 工作流页面及 Win11 虚拟机中的旧编辑器：旧版只支持拖动节点，
  没有连接端口，必须通过属性面板添加边；固定尺寸画布和重复导航还会遮住节点。
  编辑器现采用 React Flow：拖拽端口连接/重连、条件双出口、选择/删除连线、Shift 框选、
  缩放/平移/适应画布、自动整理、节点搜索/复制、撤销/重做，属性面板可关闭。
  工作流编辑时隐藏 Coze 内层导航，描述移到设置，画布填满剩余高度；Remote AI 的独立 Coze tab 保持不变。

  拒绝自连接、重复连接、回路和非法端口；条件的两个出口允许连接同一目标。
