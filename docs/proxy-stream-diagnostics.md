# 模型回复中断诊断

模型回复中断时，电脑端自动记录诊断信息，无需提前开启调试，也不需要重新发送对话来收集日志。
手机、Web 和桌面聊天经过同一电脑端代理时，均使用这套记录。
在设置中导出诊断日志即可获取当前文件、上一份轮转文件及代理错误历史。

## 记录范围

- 请求信息：请求标识、会话标识摘要、模型、推理设置、Lite 协议状态、账户摘要及请求体大小和结构摘要。
- 请求过程：每次上游尝试、代理重试原因及等待时间、HTTP 状态、允许记录的响应头。
- 上游错误：错误消息、类型、错误码、参数、状态、重试等待提示、未完成原因及上游请求标识摘要。
- 流式进度：事件总数、最近 12 组事件类型及连续次数、最后的事件序号、响应标识摘要。
- 中断位置：首字节与末字节时间、末字节后的等待时间、收到的字节数、是否收到完成事件。
- 结束方式：正常读完、上游错误、读取错误或下游提前停止读取；读取错误同时保留脱敏后的底层原因链。

HTTP 200 不代表模型回复成功。例如上游返回 `response protection is unavailable` 时，
`response_stream_error` 的 `details` 会保留对应错误类型和错误码，
`response_stream_finished` 的 `stream` 会保留错误和流式进度摘要。
无 Content-Type 的 JSON 错误、已缓冲的错误响应以及没有结束分隔符的错误事件也会被分析。

## 关联排查

日志位于应用数据目录的 `logs/local-proxy-diagnostics.jsonl`。
按 `requestId` 关联 `request_received`、`upstream_http_result`、
`response_stream_error` 和 `response_stream_finished`；独立的 CLI 重试可按
`request_received.headers.threadId.hash` 和时间关联，不会误计为代理内部重试。
版本 3 新增毫秒时间戳 `tsMs`，保留原有秒级 `ts`。

## 隐私与限制

这是一份脱敏诊断记录，不是完整网络抓包。不记录请求正文、正常回复、工具输出、认证头或 Cookie；
错误内容仅提取允许的结构化字段，并对凭据和本地路径脱敏。分享前仍应检查上游错误消息。
单个事件或 JSON 响应最多分析前 64 KiB；超限记录 `captureTruncated` 或 `truncatedEvents`，
错误字段超过 2,000 字符会标记 `fieldsTruncated`。无法解析的内容只记录长度和错误捕获摘要，
不把未知文本当成安全的错误正文。日志超过 10 MiB 后轮转，仅保留当前和上一份文件。

诊断只观察已读取的数据，不预读、不重放请求，也不改变取消和重试行为。
新增信息只对更新后的请求生效，不能补回旧日志中未保存的内容。
